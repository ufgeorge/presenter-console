# Sprint 1 實機驗證測試指引

> 版本：2026-08-22 · 對應 issue #1 DoD 中需要實體環境的項目
> 前置：Windows 11 + .NET 8 SDK + PowerPoint（Desktop 版）+ 手機（iOS/Android 皆可）

## 0. 準備

1. 準備一份 **40–50 頁、含講者備註** 的簡報檔（`.pptx`，每頁寫幾行備註，方便驗證 Notes 同步）
2. 手機與電腦連**同一 WiFi**（先測 LAN，再測熱點）

## A. 基本連線（確認閉環通）

1. 用 PowerPoint 開啟簡報 → **按 F5 開始放映**（這步先做）
2. 啟動 Agent：
   ```
   cd <repo> && dotnet run --project src/PresenterConsole.Desktop
   ```
   （或直接跑 build 出來的 exe）
3. Agent 視窗出現 **QR Code**，視窗顯示「目前頁碼：1/45」類似的資訊
4. 手機相機掃 QR → 開啟 PWA 頁面
5. 預期：
   - 手機狀態列顯示 **「已連線」**
   - 手機頁碼 = PowerPoint 目前頁（1/N）
   - 手機 Notes 區顯示第 1 頁的講者備註

**⚠ 常見卡點**：手機頁碼顯示「—」或狀態卡「連線中…」→ 確認手機和電腦同一個 WiFi；Agent 視窗有沒有顯示 QR（有 QR = server 已啟動）。

## B. 200 次混合換頁（核心驗收）

**每一種方式操作後，看手機頁碼有沒有立即變成 PowerPoint 的實際頁碼**（尤其「電腦端換頁」時手機沒按按鈕，靠事件同步）。

| # | 操作方式 | 次數 | 通過標準 |
|---|---|---|---|
| 1 | 手機按 **NEXT ▶** | 25 | 每次手機頁碼 +1，等於 PowerPoint |
| 2 | 手機按 **◀ PREV** | 25 | 每次手機頁碼 -1，等於 PowerPoint |
| 3 | **電腦鍵盤**方向鍵 →（PowerPoint 放映中） | 25 | 手機頁碼跟著 +1（不碰手機） |
| 4 | **滑鼠點擊**換頁（放映中按一下） | 25 | 手機頁碼跟著變 |
| 5 | **簡報筆**（有的話） | 20 | 手機頁碼跟著變 |
| 6 | PowerPoint 放映中**右鍵 → 跳頁**（或 Goto） | 20 | 手機頁碼跳到目標頁 |
| 7 | 手機 + 鍵盤**亂序混用** | 60 | 全程頁碼一致 |
| 8 | 中途在某頁停留時，檢查**手機 Notes 是否等於該頁備註** | 抽查 ≥10 頁 | 每頁 Notes 正確 |

**通過標準**：200 次內頁碼零不一致；Notes 抽查全對。
**記錄**：任何一次頁碼沒跟上 → 記下「第幾次、哪種操作、手機顯示 vs PowerPoint 實際」。

## C. 手機熱點模式（不依賴現場 LAN）

1. **手機 A** 開個人熱點（設定 → 個人熱點 → 開啟）
2. 電腦斷開原本 WiFi，**連上手機 A 的熱點**
3. 重新啟動 Agent（IP 會變，會顯示新 QR）
4. **手機 B（或平板）連同一個熱點** → 掃 QR → 控制
   - ⚠ 手機 A 開熱點後自己無法當控制端連到熱點內的電腦，需要第二支裝置
5. 預期：連線成功、翻頁正常、Notes 正常 — 證明完全不需要現場 LAN

## D. Wake Lock / NoSleep 10 分鐘

1. 手機以 `http://<電腦 LAN IP>:5217`（非 `localhost`）連線，記下開始時間，**放著不動**。
2. 若瀏覽器支援 secure context 的原生 Wake Lock，預期不顯示警告；若是 LAN HTTP，預期使用 NoSleep 隱藏影片 fallback。
3. LAN HTTP 首次連線若顯示「需要點擊才能保持螢幕亮著」，按 **[重新啟用]**；這個點擊是 iOS Safari 與 Android Chrome 允許影片播放所需的使用者互動。
4. 5 分鐘後檢查：**手機螢幕是否仍亮著**（iOS Safari、Android Chrome 各一次）。
5. 中途把瀏覽器切到背景幾秒再切回來 → fallback 重新啟用，狀態列仍正常。
6. 若仍無法保持：依頁面指引暫時關閉自動鎖定。iOS 路徑是「設定 → 螢幕顯示與亮度 → 自動鎖定 → 永不」；Android 路徑是「設定 → 顯示 → 螢幕逾時／休眠」。測試完成後恢復原設定。

研究結論：NoSleep.js 以隱藏、靜音、循環影片避免螢幕休眠，且官方文件要求 `enable()` 放在使用者輸入事件中；因此本頁在自動啟用失敗時保留可點擊的重新啟用按鈕。NoSleep.js 為 MIT 授權，官方來源與限制見 <https://github.com/richtr/NoSleep.js>。
## E. Resume / 斷線重連

| 情境 | 操作 | 預期 |
|---|---|---|
| 1. 重整 | 翻到第 17 頁 → 手機瀏覽器**重新整理** | 自動重連 → 頁碼恢復 17、Notes 正確 |
| 2. 斷網 | 手機關 WiFi 再開 | 3 秒內自動重連，狀態恢復 |
| 3. Agent 重啟 | 關掉 Agent 視窗再重開（簡報還開著） | 手機重連後頁碼恢復實際值 |
